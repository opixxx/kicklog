# KickLog — PRD (Product Requirements Document)

> 본 문서는 2026-05-21에 진행된 `/grill-me` 인터뷰 기반 의사결정의 결과물이다.
> 결정의 옵션 비교와 채택 이유는 `adr/0001-mvp-scope.md`에 있다. 본 문서는 **무엇을** 만드는지만 정의한다.

---

## 1. 제품 개요

**KickLog**는 애플워치를 차고 조기축구를 뛴 사용자에게 경기 후 개인 데이터 리포트를 제공하는 iOS 앱이다.

- 이동거리, 평균/최고 심박, 최고 속도, 스프린트 횟수
- 쿼터별 체력 변화 (평균 속도·평균 심박·스프린트 횟수)
- 메타데이터 (상대팀·결과·포지션·골·어시·운동장)
- 친구 추가 후 친구의 데이터 read-only 열람

## 2. 타깃 사용자

- **1차**: 본인 + 본인의 조기축구 팀원 (iOS 사용자)
- **2차 (TestFlight 후)**: 일반 공개 (앱스토어 정식 출시)
- 단, 팀 안에 Android 사용자도 존재 → MVP는 팀 단위가 아닌 **1:1 친구 모델**

## 3. 시나리오

### 3.1 조기축구의 구조 (도메인 가정)
- 1경기 = 2시간 = **25분 × 4쿼터**
- 사용자는 전 쿼터를 뛰지 않을 수 있음 (예: 1·3·4쿼터만 출전)
- 사용자는 출전한 쿼터마다 워치에서 **Apple 기본 운동 앱의 Soccer 워크아웃**을 직접 시작/종료한다
- 결과: HealthKit에 25분짜리 워크아웃이 1~4개 기록됨

### 3.2 사용 흐름 (Happy Path)
1. 사용자가 앱을 처음 설치 → 온보딩 4페이지 → Sign in with Apple → HealthKit 권한 허용
2. (앱 종료 후 일상) 워치에서 조기축구 출전 쿼터마다 Soccer 워크아웃 시작/종료
3. (경기 후) 사용자가 앱을 연다 → 메인 화면에 "라벨링 필요한 경기" 카드 표시
4. 카드 탭 → 라벨링 화면:
   - **자동으로 묶인 워크아웃 그룹** + 사용자가 "내가 뛴 쿼터" 체크 (예: 1·3·4)
   - 메타데이터 입력 (상대팀·결과·포지션·골·어시·운동장 — 모두 optional)
   - 30분 초과 워크아웃이 있으면 경고 + 시작/종료 시각 슬라이더로 trim
5. 저장 → 경기 리포트 화면으로 이동 → 자동으로 백엔드 업로드 (친구가 볼 수 있게)
6. 친구 탭에서 친구의 데이터를 read-only로 열람

## 4. 핵심 기능 (MVP 스코프)

### 4.1 분석 지표

| 지표 | 출처 | 정의 |
|---|---|---|
| 이동거리 | HealthKit | `distanceWalkingRunning` |
| 평균/최고 심박 | HealthKit | `heartRate` |
| 활성 에너지 | HealthKit | `activeEnergyBurned` |
| 최고 속도 | `HKWorkoutRoute` GPS | 1초 이동평균 후 max, 1초 이상 유지된 값만 |
| 스프린트 횟수 | GPS 속도 시계열 | **14 km/h 이상 1초 이상 유지된 구간 카운트** (코드 상수, 화면에 기준 표기) |
| 쿼터별 체력 변화 | 위 지표 쿼터별 집계 | 평균 속도(헤드라인) + 평균 심박 + 스프린트 횟수 — 3종 막대그래프 |

### 4.2 경기 식별 & 라벨링

- **자동 그룹핑**: 시간 인접 + 같은 위치(반경 100~200m, 추후 튜닝)의 Soccer 워크아웃들을 하나의 "경기"로 자동 묶음
- **사용자 확정**: 메인 카드에서 라벨링 화면 진입 → 체크박스로 "내가 뛴 쿼터: ☑Q1 ☐Q2 ☑Q3 ☑Q4" 확정
- **30분 임계 경고**: 워크아웃 길이가 30분 초과면 종료 깜빡한 것으로 의심 → 경고 + 시작/종료 시각 슬라이더 제공

### 4.3 메타데이터 (모두 optional)

- 상대팀 (자유 텍스트)
- 경기 결과 (승 / 무 / 패)
- 본인 포지션 (GK / DF / MF / FW)
- 본인 골 수 (정수, 0~9)
- 본인 어시스트 (정수, 0~9)
- 운동장 (GPS 좌표 기반 자동 인식 — 첫 등록만 사용자가 이름 지정)

### 4.4 친구 기능

- **1:1 양방향 친구**: 요청 → 수락 → 친구 (팀 단위는 v1.1+)
- **친구 추가**:
  - 메인: **초대 링크** (Universal Link, 단톡방 공유용)
  - 보조: 사용자명 검색
- **공개 범위**: 친구는 본인의 모든 경기 + 모든 지표를 볼 수 있음 (read-only). 단 설정에서 **"심박수를 친구에게 숨기기" 토글 1개** 제공.
- **업로드 시점**: 라벨링 완료 누르는 순간 자동 백엔드 업로드 (별도 공유 버튼 없음). 첫 라벨링 시 1회 안내.

### 4.5 UX 구조

- **탭 (4탭)**: 경기 / 시즌 / 친구 / 설정
- **한 경기 리포트** (단일 페이지 스크롤):
  ```
  [헤더] 2026-05-21 (수) 09:00 · ○○공원 풋살장A · vs FC블루스 4-2 승
         포지션: MF · 본인 2골 1어시
  ─────────────────────────────────
  [요약 4지표] 3.2km · 19.4km/h · 14회 · 158bpm 평균
  [쿼터별 차트] 평균 속도(헤드) / 평균 심박 / 스프린트 횟수 — 각 4개 막대
  [메타데이터]
  [공유 버튼]
  ```
- **시즌 탭** (자동 연도별, 카드 6개):
  - 시즌 누적 거리
  - 시즌 누적 골/어시
  - 승무패 + 승률
  - 시즌 베스트 (최고 속도 / 최장 경기 거리 / 최다 스프린트)
  - 출전 (경기 수 / 누적 쿼터 수)
  - 평균 (경기당 거리 / 평균 심박)
- **친구 탭**: 친구 리스트 + 친구 시즌 통계 + 친구 경기 리포트 (read-only)

### 4.6 진입 흐름 (MVP)

- **Passive**: 사용자가 직접 앱 열기 → 메인 화면에 라벨링 대기 카드 표시
- **HealthKit Observer Query**: 백그라운드에서 새 Soccer 워크아웃 감지하면 자동 import
- 푸시 알림은 **v1.1**

### 4.7 온보딩 (4페이지)

1. 앱 소개 (한 줄 카피)
2. 워치 가이드 — Apple Watch에서 Soccer 워크아웃 시작/종료 방법 (사용자 직접 캡처 스크린샷)
3. **로그인 — Sign in with Apple + 카카오로 시작하기 두 버튼 (ADR-0003 D7)**
4. HealthKit 권한 (이유 명시 — `NSHealthShareUsageDescription`)

- 위치 권한은 첫 라벨링에서 "운동장 등록" 시점에 deferred
- 사용자 프로필 (키·몸무게·생년월일)은 HealthKit에서 자동 읽기 (별도 입력 X)

### 4.8 운동장 등록 흐름 (ADR-0003 D6.1)

- 라벨링 화면에서 자동 GPS 매칭 (반경 100m, iOS Haversine)
- 매칭 안 되면 "운동장 처음? 이름 입력" 카드 → 자동 GPS 좌표로 등록
- 사용자가 정확한 위치 원하면 **카카오 검색** 옵션 (백엔드 프록시 경유)

## 5. 백엔드

| 영역 | 결정 |
|---|---|
| 언어/프레임워크 | Kotlin + Spring Boot 4 |
| DB | PostgreSQL 15 |
| 인증 | Sign in with Apple + **Kakao Login** + JWT (Access 1h + Refresh 90d) |
| API | REST |
| 운동장 검색 | **카카오 로컬 API (백엔드 프록시)** |
| 사용자 삭제 | Soft delete + 30일 grace + cron hard delete |
| 동기화 | iOS → Server fire-and-forget + 재시도 (PUT 멱등) |
| 빌드 | Gradle |
| 마이그레이션 | Flyway |
| 호스팅 (예정) | Railway / Fly.io |

### 백엔드의 책임
- 사용자 계정 (Sign in with Apple)
- 친구 관계 그래프
- 본인 경기 데이터 영속화 (메타데이터·집계 지표·쿼터 라벨링 결과)
- 친구의 데이터 read API (권한 검증 포함)
- 운동장 마스터 (v1.1: 공유 운동장 DB)

### 백엔드가 하지 않는 일
- **데이터 정제·집계·분석은 iOS에서 처리** (스프린트 계산, 쿼터별 통계 등)
- 폰의 계산 능력이 충분하고, 네트워크 왕복 비용이 크고, 오프라인에서 작동해야 함

## 6. 스코프 외 (v1.1+, v2+)

### v1.1 후보
- 팀 단위 기능 (팀 생성/가입/팀 통계)
- 푸시 알림 (경기 후 자동, 친구 새 경기)
- 좋아요/댓글/활동 피드
- 비교 화면 (나 vs 친구)
- 위젯
- HealthKit 데이터 export

### v2 후보
- 풋살 모드 (실내, GPS 없는 데이터 모델 분기)
- 자체 watchOS 앱 (실시간 표시, 자동 쿼터 분할, 워치에서 메타데이터 입력)
- 사용자 정의 시즌 (커스텀 기간)
- 운동장별/포지션별 통계
- 개인화 스프린트 임계값 (본인 최고속도의 80% 자동 적용)
- 심박수 회복 측정
- ML 기반 이상 탐지 / 컨디션 예측

## 7. 일정 (목표)

- **MVP 개발**: 10~14주 (iOS + 백엔드 동시)
- **TestFlight 베타**: 본인 + 팀원 약 10~20명, 3개월 (= 한 시즌)
- **정식 출시**: TestFlight 만족 시점 (예상 6~9개월 후)
