## 1. 목표 (Goal)

KickLog 사용자가 카카오 장소 검색 결과나 직접 입력한 좌표를 개인 운동장으로 저장하고 다시 조회할 수 있는 Venue API를 구현한다. 이후 경기 라벨링에서 사용자가 자주 가는 운동장을 빠르게 선택할 수 있도록 백엔드 기반을 만든다.

## 2. 접근 (Approach)

- API
  - `POST /venues` 인증 필요: 운동장 생성. 같은 사용자의 같은 카카오 `provider/providerPlaceId`는 기존 venue를 200으로 재사용한다.
  - `GET /venues` 인증 필요: 내 운동장 목록.
  - `GET /venues/{id}` 인증 필요: 내 운동장 상세.
- Request/Response
  - Request: `name`, `geoLat`, `geoLng`, `address?`, `roadAddress?`, `provider?`, `providerPlaceId?`
  - Response: `id`, `name`, `geoLat`, `geoLng`, `address`, `roadAddress`, `provider`, `providerPlaceId`, `createdAt`
- DB
  - `V4__venues.sql` 추가.
  - `venues(user_id, name)` unique.
  - `venues(user_id, provider, provider_place_id)` partial unique where provider/provider_place_id are not null.
- 핵심 규칙
  - MVP는 개인별 운동장으로 저장한다. 공유 운동장 마스터/병합은 v1.1 이후.
  - provider 정보가 있는 검색 결과는 같은 사용자 기준 provider place id로 멱등 재사용한다.
  - provider 정보가 없는 직접 입력은 같은 사용자 내 이름 중복을 `VENUE_NAME_DUPLICATE` 409로 거부한다.
  - `/venues/{id}`는 소유자만 조회 가능하며 타 사용자 venue는 `VENUE_NOT_OWNED` 403.
  - 좌표는 `NUMERIC(9,6)`에 맞춰 소수 6자리까지 저장한다.

- `VenueService.createVenue`는 신규 venue를 저장한다.
