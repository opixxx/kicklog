## 1. 목표

2026-09-06 9일 마비의 **마지막 안전망**을 만든다.

스왑이 없으면 메모리가 차는 순간 커널이 OOM killer 대신 **무한 스래싱**에 빠진다.
프로세스가 죽지 않으므로 `restart` 정책도 작동하지 않고, 호스트 전체가 산 채로 마비된다.
실제로 그렇게 됐다.

스왑이 있으면 메모리 부족 시 스왑을 쓰다가, 그마저 차면 **OOM killer 가 정상 발동**한다.
→ 마비 대신 **프로세스 사망 → 재시작 → 복구**.

## 2. 접근

| 대상 | 변경 |
|---|---|
| 현재 인스턴스 | SSM 으로 즉시 적용 (user-data 는 첫 부팅에만 실행되므로) |
| `infra/terraform/user-data.sh` | 스왑 생성 + swappiness 섹션 추가 (인스턴스 재생성 대비) |

```bash
fallocate -l 2G /swapfile && chmod 600 && mkswap && swapon
echo '/swapfile none swap sw 0 0' >> /etc/fstab     # 재부팅 유지
echo 'vm.swappiness=10' > /etc/sysctl.d/99-kicklog-swap.conf
```

### 설계 근거

- **크기 2GB** — 물리 916MB 의 2배 남짓. 디스크 30GB 중 27GB 여유라 부담 없다.
- **swappiness=10** — 기본 60 은 메모리에 여유가 있어도 스왑을 써서 응답 지연을 만든다.
  목적은 상시 사용이 아니라 **OOM 직전의 완충**이므로 낮게 둔다.
- **컨테이너는 스왑 사용 0** — compose 의 `memswap_limit = mem_limit` 이라
  백엔드는 512MB 초과 시 스왑으로 연명하지 않고 즉시 OOM kill → 재시작된다 (의도).
  이 스왑은 호스트 프로세스(nginx·docker·containerd·SSM agent·OS) 전용이다.
- **zram 은 생성되지 않는다** — 부팅 로그 `zram0: system has too much memory (916MB),
  limit is 800MB, ignoring`. 파일 기반 스왑을 직접 만든다.

## 4. 위험도 / 롤백

**Risk: Safe**

- 스왑 추가는 기존 동작에 영향을 주지 않는다. 메모리에 여유가 있으면 사용되지 않는다
  (swappiness=10 이라 더욱).
- 디스크 2GB 소비. 30GB 중 25GB 여유라 문제없다.
- 롤백: `swapoff /swapfile && rm /swapfile` + fstab 항목 제거.
