## 1. 목표 (Goal)

GitHub Actions에서 백엔드 변경 PR과 main push에 대해 Gradle 검증을 자동 실행한다. 로컬 훅에만 의존하지 않고 원격에서도 `backend ./gradlew check`를 보장한다.

## 2. 접근 (Approach)

- `.github/workflows/ci.yml` 추가.
- `push(main)`과 `pull_request(main)`에서 실행한다.
- backend 관련 파일, Gradle wrapper, workflow 변경에만 트리거한다.
- PostgreSQL 16 service를 띄우고 `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`를 주입해 기본 profile의 JPA/Flyway 검증을 통과시킨다.

## 3. 테스트 케이스 (Test Cases)

### (3-A) 인수 시나리오 (Gherkin)

```gherkin
Feature: 백엔드 CI
  Scenario: 백엔드 변경 PR 검증
    Given backend 파일이 변경된 PR이 있다
    When GitHub Actions CI가 실행된다
    Then backend Gradle check가 PostgreSQL service와 함께 실행된다
```

### (3-B) 유스케이스 / 단위 테스트 케이스

- Happy: workflow YAML이 backend check job을 정의한다.
- Happy: PostgreSQL service와 DB 환경 변수가 workflow에 포함된다.
- Unhappy: Gradle check 실패 시 CI job이 실패한다.

## 4. 검증 (Verification)

- `bash -n scripts/start-task.sh`
- `.github/workflows/ci.yml` 내용 확인
- GitHub push 후 Actions에서 `Backend Check` job 실행 확인
