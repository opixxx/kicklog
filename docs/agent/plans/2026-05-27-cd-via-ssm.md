## 1. 목표 (Goal)

PR #47 머지 후 첫 CD 실행이 **`dial tcp ***:22: i/o timeout`** 으로 실패. 원인은 SG `ec2` 의 SSH(22) 인바운드가 `allowed_ssh_cidr = "112.147.252.10/32"` (본인 IP only — ADR-0006:200 보안 정책)이고 GitHub Actions runner IP 는 차단되기 때문. `appleboy/scp-action` + `appleboy/ssh-action` 을 **AWS SSM Run Command + S3 staging + OIDC** 정공법으로 대체해 22 포트 의존을 제거하고 main 머지 자동 배포를 복원한다. ADR-0008 로 결정 명문화.

## 2. 접근 (Approach)

### A. Terraform 신규 / 변경

#### 신규: `infra/terraform/cd.tf` (GitHub Actions 측 IAM)
- `aws_iam_openid_connect_provider "github_actions"` — `token.actions.githubusercontent.com`, audience `sts.amazonaws.com`
- `aws_iam_role "github_actions_ci"` — assume by OIDC, `Condition.StringEquals: token.actions.githubusercontent.com:sub = "repo:${owner}/${repo}:ref:refs/heads/main"`
- `aws_iam_role_policy "github_actions_deploy"` — 다음 권한만:
  - `s3:PutObject`, `s3:PutObjectAcl` on `${deploy_staging_bucket}/*`
  - `ssm:SendCommand` on EC2 instance ARN + `AWS-RunShellScript` document
  - `ssm:GetCommandInvocation`, `ssm:ListCommandInvocations` (결과 polling)

#### 신규: `infra/terraform/s3.tf` (deploy staging)
- `aws_s3_bucket "deploy_staging"` — name `kicklog-deploy-staging-${account_id}`
- `aws_s3_bucket_public_access_block` — 4개 모두 true
- `aws_s3_bucket_server_side_encryption_configuration` — AES256
- `aws_s3_bucket_lifecycle_configuration` — `expiration.days = 7` (deploy artifact 7일 후 삭제)
- `aws_s3_bucket_versioning` — disabled

#### 변경: `infra/terraform/ec2.tf`
- `aws_iam_role_policy_attachment "ec2_ssm_managed"` 추가 — `arn:aws:iam::aws:policy/AmazonSSMManagedInstanceCore`
- `aws_iam_role_policy.ec2_secrets_read.policy` 의 `Resource` 에 `aws_secretsmanager_secret.ghcr_pat.arn` 추가
- 새 `aws_iam_role_policy "ec2_deploy_bucket_read"` — `s3:GetObject` on `${deploy_staging_bucket}/*`
- (SSM Agent 는 AL2023 기본 설치 → user-data 변경 불필요)

#### 변경: `infra/terraform/secrets.tf`
- `aws_secretsmanager_secret "ghcr_pat"` 신규 (`name = "kicklog/ghcr-pat"`, recovery 7d)
- `aws_secretsmanager_secret_version "ghcr_pat"` (var.ghcr_pat 주입)

#### 변경: `infra/terraform/variables.tf`
- `ghcr_pat` (sensitive)
- `github_repo_owner` (default `opixxx`) + `github_repo_name` (default `kicklog`) — OIDC trust condition 용

#### 변경: `infra/terraform/outputs.tf`
- `github_actions_role_arn`
- `deploy_staging_bucket_name`
- `ec2_instance_id`

#### 유지: `infra/terraform/network.tf`
- SSH 22 룰은 **유지** (사용자 본인 IP/32 — 비상 fallback). 완전 제거는 v1.1 (ADR-0008 후속).

### B. `.github/workflows/cd.yml` 재설계

```yaml
deploy:
  permissions:
    id-token: write       # OIDC 필수
    contents: read
  steps:
    - actions/checkout
    - aws-actions/configure-aws-credentials  # OIDC → assume kicklog-ci-role
        role-to-assume: ${{ vars.AWS_GITHUB_ROLE_ARN }}
        aws-region: ap-northeast-2
    - aws s3 cp infra/docker-compose.prod.yml s3://${{ vars.DEPLOY_STAGING_BUCKET }}/docker-compose.prod.yml
    - aws ssm send-command \
        --instance-ids ${{ vars.EC2_INSTANCE_ID }} \
        --document-name AWS-RunShellScript \
        --comment "Deploy ${GITHUB_SHA::7}" \
        --parameters commands='[...]'  # 본 PR 의 cd.yml 참조
    - aws ssm wait command-executed
    - aws ssm get-command-invocation  # 결과 출력
```

- GitHub repository **Variables** (값 노출 OK): `AWS_GITHUB_ROLE_ARN`, `DEPLOY_STAGING_BUCKET`, `EC2_INSTANCE_ID`
- GitHub repository **Secrets** 제거 대상: `EC2_HOST`, `EC2_SSH_PRIVATE_KEY`, `GHCR_PAT` (마지막 것은 Secrets Manager 로 이전)

### C. 사용자 수동 작업 (PR 머지 전 1회)
1. `infra/terraform/terraform.tfvars` 에 `ghcr_pat = "ghp_..."` 추가
2. `cd infra/terraform && terraform apply` — IAM/S3/Secret 생성
3. `terraform output` 으로 값 확인
4. GitHub repo Settings → Variables → 3개 추가
5. GitHub repo Settings → Secrets → 기존 3개 삭제

### D. 후속 (별도 PR, 본 스코프 X)
- SSH 22 포트 룰 완전 제거 + ADR-0006:200 정책 갱신 (Session Manager 만 사용)
- terraform state 를 S3 backend 로 이전 (ADR-0006 D8 후속)
- Immutable deploy (SHA tag, envsubst)
